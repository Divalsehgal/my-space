# Translations (i18n)

All static UI text lives in Contentful as `translation` entries and is baked into the site at build time. Nothing is fetched at runtime.

```
Contentful (translation entries, every locale)
        │  yarn translations   (runs automatically before dev and build)
        ▼
apps/web/src/i18n/translations/<locale>.json   ← generated, gitignored; en-US.json defines the keys and their types
        │
        ▼
t("nav.home")  — server components: getT() from "@/i18n/server"
               — client components: useT() from "@/i18n/client"
```

## Content model: `translation`

| Field | Type | Localized | Notes |
| --- | --- | --- | --- |
| `key` | Symbol, unique | no | `namespace.name`, e.g. `nav.home`, `contact.validation.emailInvalid` |
| `value` | Text | **yes** | `{name}` placeholders; plural keys end in `.one` / `.other` (plus `.few`, `.many`… where a language needs them) |
| `description` | Symbol | no | Context for translators |

## Everyday workflow

**Add a string:** create a `translation` entry in Contentful, run `yarn translations` (or restart `dev`), then use it with `t("your.key")` (unknown keys fail typecheck). Alternatively add the key to the generated `en-US.json` and run `yarn translations:push` straight away; the next sync overwrites anything that isn't in Contentful.

**Edit or translate a string:** change it in Contentful. The next build picks it up.

**Add a language:** add the locale in Contentful (Settings → Locales) and fill in the `value` fields. The next sync writes `<locale>.json` and registers it in `translations/index.ts`. Missing values fall back to English key by key.

## Commands (from `apps/web`)

| Command | What it does |
| --- | --- |
| `yarn translations` | Generate the JSON files and `index.ts` from every locale in Contentful |
| `yarn translations:setup` | Create or update the `translation` content type (Management API) |
| `yarn translations:push [--update]` | Create entries for keys only in the repo; `--update` also overwrites changed English values |
| `yarn contentful:check-tokens` | Check each Contentful token is the right kind (runs in CI); never prints values |

Three different tokens, never interchangeable:

| Variable | API | Access | Where it lives |
| --- | --- | --- | --- |
| `CONTENTFUL_ACCESS_TOKEN` | Delivery (`cdn.contentful.com`) | read-only, published | `.env`, Vercel, CI |
| `CONTENTFUL_PREVIEW_ACCESS_TOKEN` | Preview (`preview.contentful.com`) | read-only, drafts | `.env`, Vercel, CI |
| `CONTENTFUL_MANAGEMENT_TOKEN` | Management (`api.contentful.com`, starts with `CFPAT-`) | **read/write** | local `.env` and `.vscode/mcp.json` only — never Vercel or CI |

The site and the build-time sync refuse a management token in the read-only variables, and `yarn contentful:check-tokens` (run in CI) fails on any mix-up.

The translation files are not in git, so every environment that compiles the app (dev, build, CI typecheck/tests, Docker) needs `CONTENTFUL_SPACE_ID` and `CONTENTFUL_ACCESS_TOKEN`. If Contentful can't be reached, the last generated files are reused; with none on disk the sync fails.

## Rules

- Server components use `getT()`; client components use `useT()`. Never import `@/i18n/server` from a client component, because it would ship every locale to the browser.
- Use `t.plural("base", count)` for counts, not `count === 1 ? … : …`.
- Use `Intl` for dates and numbers (`Intl.RelativeTimeFormat`, `toLocaleString(locale)`); they are already locale-correct.
- Analytics labels stay in English (`id` fields) so reports don't split by language.

## Not covered yet

- **Locale routing:** every page currently renders `en-US`. Serving a second language needs URLs such as `/de/...` (`app/[locale]`), `hreflang` tags and a locale switcher. The translation layer is ready for it: pass the route's locale to `getT(locale)` and `<I18nProvider locale dictionary>`.
- **Long-form content** (hero subtitle, about paragraphs, experience, projects) still comes from the GitHub `portfolio-config` JSON. It should move to localized Contentful content types rather than key/value translations.
